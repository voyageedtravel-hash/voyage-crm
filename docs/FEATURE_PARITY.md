## Documented Deviations from Feature Parity

These features are intentionally not planned for feature parity. Each has a technical or business reason.

### D-001: Bulk deal operations — Web only
**Reason:** Bulk selecting 50+ deals and applying batch changes is a desktop workflow requiring precise multi-select on a large table. Mobile equivalent would be cumbersome and error-prone. Mobile provides single-deal operations only.
**Alternative on mobile:** Individual deal updates, batched by user over multiple actions.
**Revisit:** If mobile requests emerge from real usage, could add "select multiple" mode with numeric limits (e.g., max 5 deals).

### D-002: Bulk finance reports export — Web only
**Reason:** Exporting a 500-row CSV of ledger entries is a desktop task typically followed by opening it in Excel/Google Sheets. No mobile workflow benefits from this.
**Alternative on mobile:** Filtered views + share single-page PDF summary.
**Revisit:** Not planned.

### D-003: WhatsApp share via web.whatsapp.com — Web only
**Reason:** Mobile has a superior native WhatsApp deep link (`whatsapp://send?text=...`) that opens the WhatsApp app directly. The web fallback via `web.whatsapp.com` only serves users who don't have the mobile app open.
**Alternative on mobile:** Native WhatsApp deep link (better UX).
**Revisit:** Not needed — mobile solution is strictly better.

### D-004: Push notifications — Mobile only
**Reason:** Web push notifications require the browser to be open or a service worker to be registered. Practical delivery rates are poor. Mobile push (via FCM/APNs) reaches users reliably.
**Alternative on web:** In-app notification center visible when the CRM tab is open.
**Revisit:** Could add PWA push in Phase 10 if adoption of the PWA is meaningful.

### D-005: Bulk data export (CSV, Excel) — Web only
**Reason:** Same as D-002. Bulk exports are desktop workflows.
**Alternative on mobile:** Server generates the file and emails it to the user.
**Revisit:** Not planned.

### D-006: Biometric login — Mobile only
**Reason:** Face ID / Touch ID / fingerprint are mobile-native. WebAuthn on web is possible but rarely used in practice for password-based apps. Password + session timeout is sufficient on desktop.
**Alternative on web:** Traditional password (with password reset).
**Revisit:** WebAuthn could be added in future if desktop team demands it.

### D-007: Backup download / restore UI — Web only (admin only)
**Reason:** Downloading a large JSON file to a phone and then re-uploading it is impractical. Backup workflows are admin-tier operations that always happen from a desktop.
**Alternative on mobile:** Trigger email backup (button present). For restore, admin uses desktop.
**Revisit:** Not planned.

## Discipline

- **Every new feature must be added to this file** in the PR that introduces it, before merge.
- **Deviations require an ID (D-NNN)** and a paragraph explaining why.
- **Quarterly review:** each existing 🚫 entry re-evaluated — is the reason still valid?
- **CI check (future):** PR labeled with `feature` that doesn't touch this file blocks merge.
